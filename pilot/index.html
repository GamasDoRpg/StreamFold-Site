From installation to your second transfer

Getting started.

Run a local evaluation first. The commands below use PowerShell on Windows.

Use a non-critical sample and keep independent source copies. Replace example paths with your own.
1Install and verify the application

Run DEXIS-Setup.exe, review the license and complete installation. Open a new PowerShell window so the updated PATH takes effect.

PowerShell
dexis --version
dexis --help

Expected version: DEXIS 0.4.0. Python, Rust and pip are bundled or unnecessary for installer users.

2Pack, inspect and reconstruct a sample

In a working folder, create a sample directory with copies of a few representative files. DEXIS writes sample-v1.dxis as a directory containing the complete package.

PowerShell · sample project
dexis pack .\sample -o .\sample-v1.dxis
dexis inspect .\sample-v1.dxis
dexis verify .\sample-v1.dxis --level full
dexis unpack .\sample-v1.dxis -d .\restored-v1

Inspect separates logical bytes, unique raw bytes and stored chunk bytes. Deduplication and compression are different savings mechanisms.

The input root name is preserved: your files will be reconstructed under restored-v1\sample.

3Start a local receiver

For the first test, run the receiver on the same computer. Set a long random token of your own. Use the same token in both terminal windows; the example text below must be replaced.

PowerShell · terminal 1
$env:DEXIS_TOKEN = "REPLACE_WITH_YOUR_OWN_LONG_RANDOM_SECRET"
dexis serve --root .\received --host 127.0.0.1 --port 8741

Keep this window running. In a second PowerShell window, open the folder containing your sample package and send it:

PowerShell · terminal 2
$env:DEXIS_TOKEN = "REPLACE_WITH_YOUR_OWN_LONG_RANDOM_SECRET"
dexis send .\sample-v1.dxis http://127.0.0.1:8741

This HTTP example binds to loopback for testing on one computer. Transfers between computers need a planned receiver setup; use HTTPS on untrusted networks. Ask StreamFold about your deployment.

4Send the next version

Keep the receiver and its received directory. Edit a few files in your sample, then create a new package and send it from the same second terminal.

PowerShell · terminal 2
dexis pack .\sample -o .\sample-v2.dxis
dexis inspect .\sample-v2.dxis
dexis verify .\sample-v2.dxis --level full
dexis send .\sample-v2.dxis http://127.0.0.1:8741

DEXIS checks validated content already at the receiver and uploads missing chunks. Compare the two transfers. Actual reuse depends on matching raw bytes, not visual similarity between files.

Keep received packages and the shared cache intact. To resume an interrupted send, rerun the send command for that same package.

5Record the results

Record source size, packing time, unique raw bytes, stored bytes, transfer time and observed reuse for each version. Include DEXIS version, Windows version and whether the test used loopback or a network.

Loopback is useful for verifying the workflow. Measure your actual connection separately before drawing conclusions about network performance.

Common questions
PowerShell cannot find the dexis command.

Open a new terminal after installation. If the command is still unavailable, confirm the installation completed and contact StreamFold with the installer version and error message.

The second transfer did not reuse much content.

Reuse requires identical raw chunks at the receiver. Confirm that both transfers use the same receiver root and that earlier content is still present. Compressed or re-encoded source files can change substantially between revisions.

How do I uninstall DEXIS?

In Windows, open Installed apps, select DEXIS and choose Uninstall. You can also use the Uninstall DEXIS entry in the Start Menu.
