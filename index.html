A practical workflow for technical teams

Easy to inspect.
Ready to evaluate.

Pack, inspect, verify and send with a single CLI. See how much content is unique, check package integrity and evaluate transfer behavior on the datasets your team actually uses.

DEXIS CLI0.4
# Package a project version
$ dexis pack /projects/shot-010 -o shot-010.dxis

# Inspect content and verify the package
$ dexis inspect shot-010.dxis
$ dexis verify shot-010.dxis --level full

# Send to your configured receiver
$ dexis send shot-010.dxis \
    https://receiver.example:8741 --workers 8

Example commands. Replace paths and receiver address for your environment.

The technology behind the transfer

Content-aware by design.

CHUNKINGContent-defined boundaries

FastCDC-style chunking identifies boundaries from file content. A native Rust/PyO3 scanner handles the bytewise hot path, with a matching Python fallback as the reference path.

IDENTITYBLAKE2b-256 over raw bytes

Chunk identity comes from the original, uncompressed bytes. Compression choices do not change how DEXIS identifies the underlying content.

STORAGEAdaptive RAW / Zstandard

Adaptive mode probes new unique chunks and keeps Zstandard only when the complete chunk meets the configured savings threshold. Otherwise, it stores the raw content.

REBUILDSelf-contained manifests

SQLite manifests record exact reconstruction maps. Packages remain self-contained, without a permanent dependency on the receiver’s shared cache.

The receiver can reuse validated matching content from earlier packages. When an encoding differs, DEXIS can attempt local re-encoding before requesting an upload.
